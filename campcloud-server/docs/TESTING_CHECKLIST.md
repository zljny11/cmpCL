## 🔬 手工验收清单（关键路径）

### 登录认证
- [ ] User 用正确密码登录成功
- [ ] User 用错误密码登录失败，提示"用户名或密码错误"
- [ ] Token 过期后刷新页面被跳转到登录页
- [ ] Admin 登录成功
- [ ] Admin 和 User 登录后可以互相跳转 `/admin/` 路由（User 应被拒绝）

### 用户侧：完整链路
```
1. 登录
2. 补充信息（跳转或弹窗）
3. 创建需求
4. 上传数据（如果需要）
5. 查看需求列表
6. 点击进入需求详情
7. 查看三层结构（Patient → Study → Series）
8. 发送留言
```

**验收标准：**
- [ ] 每步都能正常进行，无报错
- [ ] 创建的需求出现在列表中
- [ ] 详情页能展示三层数据
- [ ] 留言成功发送

### Admin 侧：完整链路
```
1. Admin 登录
2. 进入需求列表
3. 点击某个用户的需求
4. 修改需求状态为 processing
5. 回复留言
6. 上传交付物
7. 修改需求状态为 completed
```

**验收标准：**
- [ ] 需求列表显示所有用户的需求（不仅是自己的）
- [ ] 状态修改成功，前端界面立即更新
- [ ] 状态修改后对应 user 能收到通知
- [ ] 留言发送成功
- [ ] 交付物上传成功，用户侧能看到下载链接

### 通知验收
- [ ] User 收到 admin 改状态的通知
- [ ] User 收到 admin 回复留言的通知
- [ ] User 收到交付物上传的通知
- [ ] Admin 收到 user 发留言的通知
- [ ] Admin 收到 user 上传补充数据的通知
- [ ] 通知已读标记正常工作
- [ ] 未读通知数正确显示

### 特殊边界检查
- [ ] User A 无法看到 User B 的需求（无论通过 URL 还是列表）
- [ ] User 尝试访问 `/admin/requirements` 被重定向或拒绝，不是白屏
- [ ] 同一需求单修改状态 + 发留言，应该生成 2 条通知（不合并）
- [ ] 多次上传补充数据，每次都触发 admin 的通知
- [ ] 状态转移日志正确记录（可通过 DB 查询验证）

1. **DICOM 解析复杂性**
   - 解析逻辑有 ~200 行 private 方法
   - 未来可补充更多单元测试
   - 建议前期使用测试 DICOM 文件验证

2. **文件存储**
   - 目前使用本地磁盘存储
   - 未在测试中验证磁盘操作
   - 建议生产环境配置磁盘配额和清理策略

### 手工验收依赖
1. 需要 2 个测试账号（user + admin）
2. 需要能正常上传文件的测试环境
3. 建议使用小 DICOM 文件或自定义测试数据
